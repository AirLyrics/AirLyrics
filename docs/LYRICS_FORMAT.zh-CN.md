# 歌词格式

[English](LYRICS_FORMAT.md) · [简体中文](LYRICS_FORMAT.zh-CN.md)

AirLyrics 支持本地导入 `.lrc` 和 `.ttml` 文件。

## 普通 LRC

推荐每行使用一个时间戳：

```lrc
[00:12.34]这是一行歌词
[00:15.60]这是下一行歌词
```

时间戳格式为 `[mm:ss.xx]`，分别表示分钟、秒和百分秒。

## 翻译歌词

原文和翻译可以写在同一行，中间使用 ` / ` 分隔：

```lrc
[00:12.34]大好きだって 大切だって / I love you, I love you
```

也可以使用相同时间戳分行书写：

```lrc
[00:12.34]大好きだって 大切だって
[00:12.34]I love you, I love you
```

导入时，第一行作为原文，后续不同文本作为翻译，并自动转换为单行格式。

## 逐字 LRC

逐字歌词仅支持本地导入，每个原文行需同时包含行时间戳和字词时间戳：

```lrc
[00:12.34]<00:12.34>I <00:12.60>love <00:12.95>you
```

翻译使用与原文相同的行时间戳，无需添加字词时间戳：

```lrc
[00:12.34]<00:12.34>大<00:12.60>好き<00:12.95>だって
[00:12.34]I love you, I love you
```

普通歌词与逐字歌词不能同时独立保存，导入另一类型前需先移除现有歌词。导入逐字歌词后，
AirLyrics 会自动生成并同步普通 LRC；修改或移除歌词时，请操作逐字歌词。

## TTML

AirLyrics 支持 TTML 子集，并兼容 Apple Music 与 AMLL 中部分常见的 TTML 时间和翻译字段。

逐行 TTML 在每个 `<p>` 标记时间：

```xml
<tt xmlns="http://www.w3.org/ns/ttml">
  <body>
    <div>
      <p begin="00:12.340" end="00:15.600">这是一行歌词</p>
      <p begin="00:15.600" dur="2.400s">这是下一行歌词</p>
    </div>
  </body>
</tt>
```

逐字 TTML 还会在歌词 `<span>` 上标记时间：

```xml
<tt xmlns="http://www.w3.org/ns/ttml">
  <body>
    <div>
      <p begin="00:12.340" end="00:15.600"><span begin="00:12.340" end="00:12.600">I </span><span begin="00:12.600" end="00:13.100">love </span><span begin="00:13.100" end="00:15.600">you</span></p>
    </div>
  </body>
</tt>
```

TTML 时间支持 `00:12.340`、`00:00:12.340` 等时钟格式，也支持 `12.34s` 等偏移格式。
用 `end` 标记结束时间，或用 `dur` 标记持续时间。

翻译支持带 `x-translation` 角色的内联元素，以及通过 `itunes:key` 与歌词行关联的
Apple Music 头部翻译。

导入结果由所选入口决定：

- **普通歌词** 接受逐行或逐字 TTML，逐字时间会合并为逐行时间。
- **逐字歌词** 要求每个有效歌词行都包含带时间的 `<span>`。逐行或混合时间的 TTML 无法以逐字歌词导入。

导入后，TTML 会转换为可编辑歌词，源文件不会被修改；样式和复杂的多人声表现数据不会保留。

## 兼容的 LRC 变体

也兼容以下常见变体：

```lrc
[00:12.34]歌词
[00:12:34]歌词
[01:02.345]歌词
[00:12.34][00:15.60]重复歌词
```

对一些工具导出的紧凑格式，AirLyrics 也会尝试分析：

```lrc
[00:00:58]歌词A[00:01:20]歌词B[00:02:18]歌词C
```

这种格式仅用于兼容，不建议手动编辑。

## 完整支持清单

上方是推荐写法。以下列出当前本地导入入口支持的格式与兼容写法；App 内的格式提示只保留主要示例。

### 文件与导入入口

| 文件内容 | 普通歌词入口 | 逐字歌词入口 |
| --- | --- | --- |
| 普通 LRC（含翻译） | 支持 | 不能单独作为逐字歌词；同时间的普通行可作为逐字行的翻译 |
| 逐字 LRC（行标签 + 字词标签） | 不解析字词标签，请使用逐字入口 | 支持 |
| 逐行 TTML | 支持 | 不支持 |
| 逐字 TTML | 支持，合并为逐行歌词 | 支持 |
| 逐行与逐字混合的 TTML | 支持 | 不支持，每个有效歌词行都需要字词时间 |
| AirLyrics 逐字 JSON | 不支持 | 兼容，结构见下方 |

推荐使用 `.lrc` 和 `.ttml` 扩展名。文件名或类型不明确时会尝试识别内容，但不会自动转换其他歌词格式。

### LRC 时间戳与兼容写法

下面各写法也适用于逐字标签 `<…>`：

| 时间戳示例 | 含义 |
| --- | --- |
| `[00:12]` | 12 秒，无小数 |
| `[00:12.3]`、`[00:12:3]` | 12.3 秒，一位小数 |
| `[00:12.34]`、`[00:12:34]` | 12.34 秒，两位小数 |
| `[00:12.345]`、`[00:12:345]` | 12.345 秒，三位小数 |
| `[1:02.34]` | 分钟也可以只写一位 |

分钟为 1–2 位，秒必须为两位且小于 60，小数最多三位。LRC 的第三段是秒的小数部分：`[00:00:58]` 表示 **0.58 秒**，不是 58 秒；不支持小时格式。

普通 LRC 还支持以下写法：

| 写法 | 示例与处理 |
| --- | --- |
| 一行多个时间戳 | `[00:12.34][00:15.60]重复歌词`：两个时间各显示一次 |
| 多段挤在一行 | `[00:12.34]第一行[00:15.60]第二行`：按时间标签拆分 |
| 同时间分行翻译 | 同一时间戳下，首行作为原文，后续不同文本合并为翻译 |
| 同行翻译 | `[00:12.34]原文 / 翻译`，半角 `/` 两侧需要空白 |
| 全角分隔符 | `[00:12.34]原文／翻译`，`／` 两侧可不留空格 |
| 多份翻译 | `[00:12.34]原文 / 翻译一 / 翻译二` |
| 仅有翻译 | `[00:12.34]/ 翻译`：`/` 后需留空格 |
| 空歌词行 | `[00:12.34]`：普通歌词中保留该时间点的空行 |
| 元数据 | `[ar:歌手]`、`[ti:歌名]`、`[al:专辑]`、`[by:制作人]` 等独立标签行可保留 |

`[offset:…]` 只作为元数据保留，不会调整时间轴；请使用 App 内的歌词偏移。普通歌词中的“作词：甲 / 乙”等署名行不会按翻译拆分。非空正文需要时间戳，只有元数据或空行的文件不能导入。

逐字 LRC 的补充规则：

- 每个原文行至少包含一个行标签 `[…]` 和一个有文字的字词标签 `<…>`。字词时间早于行时间时，该片段会被忽略。
- 每个原文行单独占一行，不要用多个行标签复制逐字段落。翻译另起普通 LRC 行，并使用相同的行时间。
- 字词间的空格写在文字中，例如 `<00:12.34>I <00:12.60>love <00:12.95>you`。
- 空的末尾标签不会作为结束时间。需要明确每个字词的结束时间时，使用 TTML 的 `end` 或 `dur`。

### TTML 时间与结构

| 时间写法 | 示例 |
| --- | --- |
| 时、分、秒 | `01:02:03`、`01:02:03.004` |
| 分、秒 | `02:03`、`02:03.45` |
| 纯秒数 | `95`、`95.5` |
| 带 `s` 的秒数 | `12s`、`12.34s`、`12.3456s` |

前三种写法的小数最多三位；带 `s` 的秒数允许更多小数位，会四舍五入到毫秒。时钟格式的分钟和秒均须小于 60。不支持 `ms`、`m`、`h`、帧（`f`）、节拍（`t`）单位或帧式时钟。

- 文件以 `<tt>` 为根，包含一个 `<body>`；每个歌词 `<p>` 都要有 `begin`，以及 `end` 或 `dur`。同时提供 `end` 和 `dur` 时，以 `end` 为准。若设置了 `<body dur="…">`，歌词行不能超出该时长。
- 逐字 `<span>` 同样使用 `begin` 加 `end` 或 `dur`，时间必须位于所属 `<p>` 内；非空片段的结束时间须晚于开始时间。
- 时间按歌曲起点计算，不累加父元素的 `begin`。不能只给 `<div>` 标时间，让 `<p>` 继承。
- 支持命名空间前缀。`itunes:timing="Line"` 会忽略字词时间；`Word` 或未声明时可读取带时间的 `<span>`。
- `<br/>` 转为空格，普通排版标签保留文字，不保留样式。

### TTML 翻译写法

**内联翻译**放在对应歌词行内，使用 `ttm:role="x-translation"`：

```xml
<tt xmlns="http://www.w3.org/ns/ttml"
    xmlns:ttm="http://www.w3.org/ns/ttml#metadata">
  <body>
    <p begin="12s" end="15s">Hello<span ttm:role="x-translation">你好</span></p>
  </body>
</tt>
```

**Apple Music 头部翻译**通过 `text for` 与歌词行的 `itunes:key` 对应：

```xml
<tt xmlns="http://www.w3.org/ns/ttml"
    xmlns:itunes="http://itunes.apple.com/lyric-ttml-extensions">
  <head>
    <metadata>
      <iTunesMetadata xmlns="http://music.apple.com/lyric-ttml-internal">
        <translations>
          <translation type="subtitle" xml:lang="zh-Hans">
            <text for="L1">你好</text>
          </translation>
        </translations>
      </iTunesMetadata>
    </metadata>
  </head>
  <body>
    <p begin="12s" end="15s" itunes:key="L1">Hello</p>
  </body>
</tt>
```

同一行可合并内联和头部的多份翻译，重复文本会去重。`x-bg` 背景声、`x-roman` 罗马音和 ruby 注音会被忽略，只保留主歌词；不提供独立的多人声轨道。TTML 不支持 DTD、外部实体、嵌套 `<p>` 或嵌套的带时间 `<span>`。

### AirLyrics 逐字 JSON（兼容格式）

仅通过 **逐字歌词** 入口导入，不是通用歌词 JSON。推荐仍使用 LRC 或 TTML。

```json
[
  {
    "startMs": 12000,
    "endMs": 15000,
    "text": "Hello world",
    "tokens": [
      {"text": "Hello ", "startMs": 12000, "endMs": 13000},
      {"text": "world", "startMs": 13000, "endMs": 15000}
    ]
  }
]
```

时间单位为毫秒。每行需有非空 `text`、有效起止时间和至少一个有效 `tokens` 片段。也可使用 `{"metadata": ["[ar:Artist]"], "lines": [...]}` 对象形式，其中 `lines` 为上方数组，`metadata` 可省略；行对象可带 `background` 布尔值。其他工具的 JSON 只有符合此结构才可导入。

### 不支持直接导入

纯文本歌词、SRT、ASS、QRC、KRC、YRC，以及其他加密或压缩歌词文件，需要先转换为上面列出的格式。仅修改扩展名不会完成转换。TTML 的支持范围以上述清单为准，不代表支持全部 TTML 标准。

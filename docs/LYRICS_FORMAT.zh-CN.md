# 歌词格式

[English](LYRICS_FORMAT.md) · [简体中文](LYRICS_FORMAT.zh-CN.md)

AirLyrics 支持本地导入 `.lrc` 和 `.ttml` 文件。联网歌词缺失、不准确或不同步时，您可以使用本地导入。

## 普通 LRC

普通 LRC 用于逐行显示歌词。

推荐格式：

```lrc
[00:12.34]这是一行歌词
[00:15.60]这是下一行歌词
```

格式：

```text
[mm:ss.xx]歌词文本
```

说明：

- `mm` 是分钟。
- `ss` 是秒。
- `xx` 是百分秒。
- 手动整理时，一行放一个主要时间戳和一句歌词。

## 翻译歌词

歌词包含翻译行时，AirLyrics 可以显示原文和翻译。

推荐本地格式：

```lrc
[00:12.34]大好きだって 大切だって / I love you, I love you
```

普通 LRC 导入和保存时，也支持把原文和翻译写在相同时间戳下：

```lrc
[00:12.34]大好きだって 大切だって
[00:12.34]I love you, I love you
```

导入后会归一化为：

```lrc
[00:12.34]大好きだって 大切だって / I love you, I love you
```

如果同一时间戳下存在多行翻译，第一行会作为原文，后续不同文本会作为翻译保留。

实际显示取决于歌词内容模式：

- 原文 + 翻译
- 仅原文
- 仅翻译

## 逐字 LRC

逐字歌词主要通过本地导入支持。它包含整行时间戳和行内字词时间戳。

推荐格式：

```lrc
[00:12.34]<00:12.34>I <00:12.60>love <00:12.95>you
```

格式：

```text
[整行开始时间]<字词开始时间>字词<字词开始时间>字词
```

整行时间戳决定这一行什么时候出现，行内时间戳决定字词高亮时机。

逐字歌词导入时，也可以在相同整行时间戳下提供翻译行：

```lrc
[00:12.34]<00:12.34>大<00:12.60>好き<00:12.95>だって
[00:12.34]I love you, I love you
```

如果当前歌曲没有普通歌词，AirLyrics 会根据逐字歌词自动生成普通 LRC。
存在同时间戳翻译行时，生成的普通 LRC 也会包含翻译：

```lrc
[00:12.34]大好きだって / I love you, I love you
```

如果当前歌曲已经有普通歌词，AirLyrics 不允许继续导入逐字歌词。请先移除已有普通歌词，
再导入逐字歌词。这样可以避免同一首歌同时存在两份可编辑歌词，导致显示和修改规则不一致。

导入逐字歌词后，普通 LRC 会作为逐字歌词的自动生成结果保存。之后请只修改逐字歌词；
保存逐字歌词时，AirLyrics 会重新生成普通 LRC。移除逐字歌词时，如果普通 LRC 是由逐字歌词
自动生成的，也会一起移除。

## TTML

AirLyrics 支持下述 TTML 子集，包括 Apple Music 与 AMLL 文件中常见的时间和翻译字段。

逐行 TTML 在每个 `<p>` 标记时间：

```xml
<tt xmlns="http://www.w3.org/ns/ttml">
  <body>
    <div>
      <p begin="00:12.340" end="00:15.600">这是一行歌词</p>
      <p begin="00:15.600" dur="2.400s">这是下一行歌词</p>
    </div>
  </body>
</tt>
```

逐字 TTML 还会在歌词 `<span>` 上标记时间：

```xml
<tt xmlns="http://www.w3.org/ns/ttml">
  <body>
    <div>
      <p begin="00:12.340" end="00:15.600"><span begin="00:12.340" end="00:12.600">I </span><span begin="00:12.600" end="00:13.100">love </span><span begin="00:13.100" end="00:15.600">you</span></p>
    </div>
  </body>
</tt>
```

TTML 时间支持 `00:12.340`、`00:00:12.340` 等时钟格式，也支持 `12.34s` 等偏移格式。
用 `end` 标记结束时间，或用 `dur` 标记持续时间。

翻译支持带 `x-translation` 角色的内联元素，以及通过 `itunes:key` 与歌词行关联的
Apple Music 头部翻译。样式和复杂的多人声表现数据不会保留。

导入结果由所选入口决定：

- **普通歌词** 接受逐行或逐字 TTML。逐字 span 会合并为整行文本。
- **逐字歌词** 要求存在有效的带时间 span。只有行时间的 TTML 会提示格式错误。

普通 TTML 会规范化并保存为应用管理的 LRC。逐字 TTML 会保存为内部逐字数据，并生成普通
LRC 作为回退。导入后编辑的是规范化歌词，源 TTML 文件不会被修改。

## 兼容的 LRC 变体

解析器兼容以下常见变体：

```lrc
[00:12.34]歌词
[00:12:34]歌词
[01:02.345]歌词
[00:12.34][00:15.60]重复歌词
```

也会尝试恢复一些工具导出的紧凑格式：

```lrc
[00:00:58]歌词A[00:01:20]歌词B[00:02:18]歌词C
```

不过这种紧凑格式不推荐手动维护。

## 不推荐

手动制作歌词时，请注意：

- 只有纯文本、没有时间戳。
- 单行过长且没有自然空格。
- 一个文件混入多首歌。
- 歌曲版本或时长不匹配。
- 把普通 LRC 作为逐字歌词导入。
- 把逐行 TTML 作为逐字歌词导入。
- 在已有普通歌词时直接导入逐字歌词。请先移除已有普通歌词。
- 使用逐字歌词后继续单独修改自动生成的普通 LRC。请修改逐字歌词本身。
